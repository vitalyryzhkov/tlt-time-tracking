# Одна почта — одно устройство (Cloudflare Access + Pages Function)

Зачем: Cloudflare Access пускает на сайт по коду из письма тех, чья почта есть
в списке. Но человек из списка может переслать код коллеге или войти с его
телефона — и тогда на сайте окажется кто-то, кого в списке нет. Этот код
закрывает дыру: **первый телефон, с которого вошли под почтой, запоминается,
и дальше эта почта работает только с него.** Другой телефон увидит страницу
«Этот адрес уже привязан к другому устройству. Доступ разрешён только с
одного устройства». Снять
привязку (человек сменил телефон) может только владелец.

Ничего в самом приложении (`index.html`) не менялось.

## Что где лежит

| Файл | Что это |
|---|---|
| `functions/_middleware.js` (в корне репо) | Включает защиту на Cloudflare Pages. Пять строк, вся логика импортируется из файла ниже. |
| `worker/src/index.js` | Сама логика: проверка входа Access, привязка устройства, админ-страницы. |
| `worker/test/gate.test.js` | Тесты. Запуск: `cd worker` и `npm test` (нужен Node 20+). |
| `worker/wrangler.toml` | Нужен только для варианта Б (отдельный Worker на своём домене). Для варианта А не используется. |

## Почему Pages Function, а не отдельный Worker

Задача была «Worker перед сайтом». Но у сайта на Cloudflare Pages адрес вида
`имя.pages.dev`, а **на `*.pages.dev` нельзя повесить отдельный Worker**
(Workers Routes работают только на доменах, которые добавлены в ваш аккаунт
Cloudflare как зона). Отдельный Worker потребовал бы купить домен, добавить его
в Cloudflare, привязать к нему Pages и Worker — четыре лишних шага и деньги.

У Pages есть встроенная замена: **Pages Functions** — код в папке `functions/`
того же репозитория, который Cloudflare запускает на том же адресе перед
отдачей файлов. Файл `functions/_middleware.js` выполняется на каждом запросе,
включая `/` и `/index.html`. Он живёт на том же hostname, что и Access, поэтому
вопрос «как повесить на тот же маршрут» отпадает сам.

Отдельный Worker (`worker/wrangler.toml`) оставлен на случай, если свой домен
всё же появится — см. «Вариант Б» в конце. Логика одна и та же.

## Почему проверяется подпись JWT, а не просто заголовок с почтой

Access добавляет к запросу два заголовка: `Cf-Access-Authenticated-User-Email`
(почта текстом) и `Cf-Access-Jwt-Assertion` (та же почта внутри подписанного
токена). Текстовому заголовку можно верить, только если на код **нельзя**
попасть в обход Access. У Pages это не гарантировано: пока Access включён
только на одном адресе (например, на `имя.pages.dev`), у проекта есть ещё
адреса превью `хэш.имя.pages.dev`, и запрос туда с подделанным заголовком
дошёл бы до кода без Access. Поэтому код берёт почту **только из токена и
проверяет подпись** открытым ключом вашей команды Access
(`https://<команда>.cloudflareaccess.com/cdn-cgi/access/certs`), а также
издателя (`iss`), адресата (`aud` = метка вашего приложения) и срок (`exp`).
Подделать такой токен нельзя. Цена — две переменные (`ACCESS_TEAM_DOMAIN`,
`ACCESS_AUD`), которые надо один раз скопировать из панели. Без них код никого
не пускает.

## Как это работает (для понимания)

1. Человек открывает сайт → Access спрашивает почту, шлёт код, пускает.
2. Запрос приходит в `_middleware.js`. Код проверяет токен Access и узнаёт почту.
3. Смотрит в KV (маленькая база «ключ → значение» у Cloudflare), есть ли запись
   для этой почты.
   - Записи нет → выдаёт телефону случайный номер в cookie `tlt_device`
     (срок год, HttpOnly, Secure, SameSite=Lax) и сохраняет в KV хэш этого
     номера, дату и строку браузера (User-Agent). Пускает. Номер всегда
     придумывает сервер: cookie, которую прислал сам клиент, не принимается.
   - Запись есть, cookie совпадает → пускает.
   - Запись есть, cookie другая или её нет → страница 403 на русском.
     Чужие данные (какой телефон привязан) не показываются.
4. Владелец (почта в `ADMIN_EMAIL`) видит два адреса:
   - `/admin/list` — таблица: почта, дата привязки, браузер, ссылка «сбросить»;
   - `/admin/reset?email=адрес` — удаляет привязку, следующее устройство с этой
     почтой станет новым.
   Для всех остальных эти адреса отвечают 404, как будто их нет.

Лимит устройств — константа `DEVICE_LIMIT` в `worker/src/index.js` (по
умолчанию 1). Можно переопределить без правки кода переменной `DEVICE_LIMIT`
в панели (например `2`, если у кого-то телефон и планшет).

Что хранится в KV: `email:адрес → {devices:[{hash, firstSeen, ua}]}`. Сам
номер из cookie не хранится, только его SHA-256, поэтому даже из панели KV
нельзя «скопировать» чужое устройство.

Cookie живёт год; если человек почистит cookie в браузере или переустановит
браузер, у него будет «другое устройство» и понадобится сброс. Сессия самого
Access — отдельная (её срок задаётся в приложении Access), она на привязку не
влияет.

## Шаги в панели Cloudflare (вариант А — рекомендуемый)

Предполагается, что проект Pages уже создан из этого репозитория и Access к
нему уже подключён. Если нет — сначала это (кратко в конце раздела).

### 1. Создать KV namespace

1. Панель Cloudflare → слева **Storage & Databases → KV**.
2. **Create a namespace**, имя `tlt-devices`, **Add**.
3. Больше тут ничего не нужно: записи появятся сами.

### 2. Привязать KV к проекту Pages

1. **Workers & Pages** → ваш проект Pages → **Settings** → **Bindings**.
2. **Add** → **KV namespace**.
3. **Variable name**: ровно `DEVICES` (большими буквами). **KV namespace**:
   `tlt-devices`. **Save**.
4. Если панель спрашивает про окружение — выбирать **Production** (а потом
   при желании повторить для Preview).

### 3. Задать переменные

Там же: **Settings → Variables and Secrets → Add**. Четыре штуки, тип
«Plaintext» подойдёт всем (секретов среди них нет):

| Имя | Что вписать | Где взять |
|---|---|---|
| `ADMIN_EMAIL` | ваша почта, та, под которой входите через Access | — |
| `ACCESS_TEAM_DOMAIN` | имя команды Zero Trust, **без** `.cloudflareaccess.com` | Zero Trust → **Settings → Custom Pages** (поле Team domain), либо из адреса страницы входа: `https://ЭТО.cloudflareaccess.com` |
| `ACCESS_AUD` | длинная строка из букв и цифр | Zero Trust → **Access controls → Applications** → ваше приложение. Строка **Application Audience (AUD) Tag** показана на вкладке **Overview** приложения; в других версиях панели — **Edit → Additional settings**. Копировать целиком |
| `DEVICE_LIMIT` | `1` (необязательно; `2` — если двум устройствам можно) | — |

Регистр почты не важен, код сравнивает в нижнем регистре.

### 4. Передеплоить

Привязки и переменные вступают в силу только с новым деплоем.
**Workers & Pages → проект → Deployments** → у последнего деплоя меню `⋯` →
**Retry deployment** (или просто сделать любой push в репозиторий после того,
как этот код окажется в `main`).

Настройки сборки проекта менять не нужно: папка `functions/` лежит в корне
репозитория, Cloudflare находит её сам (Build command пустой, Output directory
`/` — как и было).

### 5. Проверить

1. Открыть сайт в браузере телефона → ввести код → сайт открылся. Это первая
   привязка.
2. Открыть `https://ваш-адрес/admin/list` — должна быть таблица с одной
   строкой: ваша почта, время, браузер.
3. Открыть сайт с **другого** устройства (ноутбук) под той же почтой → после
   кода Access должна появиться страница «Этот адрес уже привязан к другому
   устройству. Доступ разрешён только с одного устройства».
4. На телефоне открыть `/admin/reset?email=ваша почта` → ответ «Привязка …
   удалена». Теперь ноутбук пройдёт и станет привязанным, а телефон — уже нет.
   Сбросить ещё раз и снова войти с телефона.
5. Дать ссылку коллеге из списка Access — он должен войти с первого раза.
6. Открыть `https://ваш-адрес/functions/_middleware.js`. Ожидается 404
   (Cloudflare не отдаёт папку `functions` как файлы). Если вдруг отдаёт код —
   это не утечка (секретов в нём нет), но скажите, уберём.

Если шаг 1 показывает страницу «Нет входа. Не удалось определить, кто вы» —
проверить `ACCESS_TEAM_DOMAIN` и `ACCESS_AUD` (опечатка, лишний `https://`
или `.cloudflareaccess.com` в домене) и что деплой после правки переменных был.

Если `/admin/list` отвечает 404 под вашей почтой — `ADMIN_EMAIL` не совпадает
с почтой, под которой вы входите через Access.

### Если Pages и Access ещё не настроены

- **Pages:** Workers & Pages → **Create** → **Pages** → **Connect to Git** →
  выбрать репозиторий `tlt-time-tracking`, ветка `main`, Framework preset
  `None`, Build command пустой, Build output directory `/`. **Save and Deploy.**
  Адрес появится вида `имя.pages.dev`.
- **Access:** Zero Trust → **Access controls → Applications → Add an
  application → Self-hosted**. Домен приложения — ваш `имя.pages.dev`
  (а если есть превью-адреса — лучше `*.имя.pages.dev`, тогда и они будут
  за Access). Политика **Allow** с правилом **Emails** и списком адресов.
  Способ входа — **One-time PIN**. Session duration — на ваш вкус (до месяца).
- Чтобы и превью-деплои (`хэш.имя.pages.dev`) закрыть, в проекте Pages:
  **Settings → General → Access policy → Enable** — Cloudflare сам создаст для
  них приложение Access. Код на превью всё равно никого не пустит без верного
  токена: превью-приложение Access имеет другой AUD, поэтому для них защита
  сработает как «Нет входа». Это нормально: превью вам не нужны.

## Вариант Б — отдельный Worker на своём домене

Нужен только если появится собственный домен в Cloudflare и захочется убрать
`functions/` из репозитория. Тогда:

1. Домен добавлен в Cloudflare как зона; Pages-проекту он назначен как Custom
   domain **или** Pages остаётся на `имя.pages.dev`, а Worker проксирует на него.
2. В `worker/wrangler.toml` заполнить `routes` (ваш домен), `ORIGIN_URL`
   (адрес Pages), `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `ADMIN_EMAIL`, `id` KV
   namespace (панель → KV → ваш namespace → ID).
3. Приложение Access перевесить на этот домен (Worker должен стоять **за**
   Access, иначе токена не будет).
4. На компьютере с Node: `cd worker`, `npx wrangler login`, `npx wrangler deploy`.
5. Удалить `functions/_middleware.js`, чтобы защита не работала дважды.

Account id в `wrangler.toml` не нужен — wrangler берёт его из `wrangler login`.

## Ограничения, о которых стоит знать

- Бесплатный тариф: Pages Functions — 100 000 запросов в день, KV — 100 000
  чтений в день. Для десятка человек это бесконечность.
- Каждый запрос к сайту делает одно чтение KV. Приложение — одна страница без
  картинок, так что это один-два запроса за открытие.
- Привязка привязана к браузеру, а не к телефону: Safari и Chrome на одном
  iPhone — два разных «устройства». Коллегам стоит сказать: пользоваться
  одним браузером (или ярлыком «На экран Домой»).
- Браузерный режим «инкогнито» теряет cookie при закрытии — там сайт работать
  не будет после первого раза.
